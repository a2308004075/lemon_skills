# Lemon Checkpoints v1.2 用户操作手册

> 面向对象：使用该技能做测试分析的人员（使用者视角）
> 适用版本：v1.2 ｜ 文档日期：2026-10-02

Lemon Checkpoints 是一个测试分析 Agent 技能：把产品需求、原型、截图或用户故事转换成**按风险排序的测试执行清单**，同时保留规则证据、待确认事项和覆盖地图。

- 适合：登录、交易、审批、数据处理、智能功能等场景的测试分析。
- 不适合：编写逐步测试用例、生成完整测试计划。
- 核心原则：**先区分"已看到的事实"和"尚未确认的规则"**，不用经验替产品做决定。

## 1. 工具简介

### 1.1 产出什么

围绕用户完成目标的业务链路，产出四层内容：

1. **输入底稿**：业务背景、测试对象、可见证据和材料限制。
2. **风险路线**：按业务链路标出阻断点、数据风险和安全风险。
3. **执行清单**：测试点分为 A 首轮冒烟、B 重点验证、C 扩展检查三个批次。
4. **覆盖地图**：用 14 个标准方向检查遗漏，记录已覆盖、待补充和不适用项。

另有一份独立的**待确认问题清单**，可按编号跟踪到关闭。

### 1.2 看懂交付物必备概念

**编号体系**

| 编号 | 含义 | 说明 |
|---|---|---|
| F-XXX | 已确认事实 | 需求原文、截图或接口文档直接证明的内容 |
| V-XXX | 验证建议 | 行业测试方法要求关注、但材料没给出规则的检查 |
| O-XXX | 待确认问题 | 不同答案会改变预期结果或风险判断的问题 |
| LC-XXX | 测试检查点 | 执行清单中的每条测试点 |
| C01–C14 | 覆盖方向 | 14 个标准测试方向，用于查漏 |

**执行批次**

| 批次 | 定位 | 什么时候执行 |
|---|---|---|
| A 首轮冒烟 | 最短成功路径、关键页面、必要输入、阻断性安全控制 | 每次构建先执行 |
| B 重点验证 | 主要失败、边界、权限、状态、重复、并发和恢复 | 功能测试主体 |
| C 扩展检查 | 兼容、性能、日志、低频组合和历史影响 | 上线前或专项执行 |

**严重度**

| 等级 | 含义 |
|---|---|
| S0 | 核心功能、安全或数据完整性问题，失败会阻止上线 |
| S1 | 主要业务能力受损，对大量用户或日常操作有明显影响 |
| S2 | 影响有限，有绕行方案 |
| S3 | 低频或低影响，可以后续处理 |

**业务链路（风险路线的默认顺序）**

进入与展示 → 信息输入 → 系统校验 → 结果反馈 → 状态保持与退出

**覆盖方向 C01–C14**

| 代码 | 方向 | 代码 | 方向 |
|---|---|---|---|
| C01 | 成功路径 | C08 | 重复与重试 |
| C02 | 失败反馈 | C09 | 服务契约 |
| C03 | 临界条件 | C10 | 持久化 |
| C04 | 访问控制 | C11 | 追溯能力 |
| C05 | 数据约束 | C12 | 运行环境 |
| C06 | 生命周期 | C13 | 容量指标 |
| C07 | 同时操作 | C14 | 变更影响 |

覆盖状态只有三种：`已覆盖`（存在可执行测试点）、`待补充`（方向适用但缺规则/数据/环境）、`不适用`（无合理触发关系，需写明原因）。

### 1.3 自动专项处理

无需手动开关，材料内容会触发对应专项检查：

- 出现**金额、计费、库存、额度、算法**等 → 叠加"计算类场景"检查（单位与精度、舍入、逆向操作、并发扣减等）。
- 出现**大模型、内容生成、推荐、识别、对话**等 → 叠加"智能功能场景"检查（多轮对话、提示词注入、指标化验收等）。

## 2. 功能清单与使用方法

本节先总览全部功能，再逐项说明“怎么用”；深入细节可按提示跳转到对应章节。

### 2.1 功能总览

| # | 功能 | 能做什么 | 使用入口 | 详细用法 |
|---|---|---|---|---|
| 1 | 多格式输入接入 | 接收需求文本、需求文档、截图、HTML 原型、接口资料、多材料组合包 | 对话中粘贴内容、提供附件或给出文件路径；CLI 用 `-i` 指定 | 2.2 节、[第 5 章](#5-支持的输入材料) |
| 2 | 四层分析框架 | 输入底稿 → 风险路线 → 执行清单 → 覆盖地图，全程证据分级 | 提供材料后自动执行，无需手动开启 | 2.3 节、1.2 节 |
| 3 | 专项场景自动加挂 | 计算类、智能功能两类专项检查 | 自动识别关键词叠加，无需操作 | 2.4 节、1.3 节 |
| 4 | 待确认问题闭环管理 | O-XXX 独立清单，含负责人/状态/确认结论跟踪字段 | 在“待确认”工作表分发确认、回填结论 | 2.5 节、[第 6 章](#6-交付物说明) |
| 5 | 多格式交付 | Excel（默认，5 个工作表）、Markdown、飞书/XMind 脑图 | 指令中说明格式；CLI 用 `--format` | 2.6 节、[第 6 章](#6-交付物说明) |
| 6 | 本地 CLI 脚本 | scan 输入检查、build 生成底稿、prompt 生成提示词 | 命令行运行 `python scripts\lemon_checkpoints.py ...` | 2.7 节、4.2 节 |
| 7 | 技能化集成 | 手动 / 自动触发，融入日常对话 | 安装后输入 `/lemon-checkpoints` 或直接描述任务 | 2.8 节、3.1 节、4.1 节 |

### 2.2 功能一：多格式输入接入

**怎么用**

- **对话方式（推荐）**：直接粘贴需求文本；截图、文档、原型作为附件提供；或说明文件路径（如“分析 `lemon-input-demos\02-requirement-document.md`”）。
- **CLI 方式**：用 `-i` 指定输入文件，例如 `python scripts\lemon_checkpoints.py build -i 需求.md -o 清单.xlsx`。
- **材料不完整也能用**：只有可见内容会列为事实（F-XXX）；不可见行为写成验证建议（V-XXX）并关联待确认问题（O-XXX）。
- **多材料组合包**：需按 manifest 说明的材料角色和合并规则组织（可参考 `lemon-input-demos\06-multi-source-package.zip`）。

各输入类型明细见[第 5 章](#5-支持的输入材料)。

### 2.3 功能二：四层分析框架

**怎么用**

- 提供材料后**自动执行**，无需任何手动开关或参数。
- 材料信息不足时，Agent 会反问**最多 6 个**会改变测试结论的问题：
  - 知道答案就直接回答（如“登录用户名不区分大小写”）；
  - 不清楚时回答“按材料现状分析”，未决问题会进入待确认清单。
- 澄清回答会直接影响测试点的预期结果和依据，建议尽量给准确规则。

编号、批次、严重度的含义见 1.2 节；完整产出过程见[第 7 章](#7-完整操作流程演示)。

### 2.4 功能三：专项场景自动加挂

**怎么用**

- **无需操作**：材料中出现对应关键词时自动叠加专项检查：
  - 计算类（金额、计费、库存、额度、算法）→ 精度与舍入、单位换算、逆向操作、并发扣减等；
  - 智能功能（大模型、推荐、对话、识别、生成）→ 多轮对话、提示词注入、越权取数、指标化验收等。
- **查询命中情况**：用 CLI `scan` 生成“输入检查”，会列出“计算类场景 / 智能功能 / 含糊表达”的识别结果。

两类场景的完整检查项见技能目录下 `references/special-scenarios.md`。

### 2.5 功能四：待确认问题闭环管理

**怎么用**（在 Excel 交付物中完成闭环）

1. 生成清单后，打开“待确认”工作表；
2. 把问题分发给产品/开发确认；
3. 确认后回填“负责人、状态、确认结论”三列；
4. 规则更新后，把确认结果补充进材料并让 Agent 重新生成——原 `O-XXX` 转为已确认事实，相关测试点依据同步更新。

**注意**：即使当前没有待确认问题，“待确认”工作表也会保留并注明“无”，请勿误判为漏项。

### 2.6 功能五：多格式交付

**怎么用**

- **默认为 Excel**，无需任何操作（5 个工作表的阅读方式见[第 6 章](#6-交付物说明)）。
- **要 Markdown**：在指令中说明“输出 Markdown”；CLI 加 `--format markdown`。
- **要脑图**：在指令中说明“输出脑图（飞书/XMind 大纲）”；CLI 加 `--format mindmap`。
- **指定保存位置**：在指令中直接给出路径；未指定时默认写到 `output/lemon-checkpoints/<需求简称>-测试执行清单.xlsx`。

### 2.7 功能六：本地 CLI 脚本

**怎么用**

- 前置条件：Python 3.7+；Excel 输出需 `pip install -r requirements.txt`（详见 3.2 节）。
- 三条命令：
  - `scan`：输入检查，识别风险信号；
  - `build`：生成交付物（默认 Excel，可切换 Markdown/脑图）；
  - `prompt`：把材料注入提示词模板。

```powershell
cd D:\develop\lemon_skills\lemon_checkpoints
python scripts\lemon_checkpoints.py scan  -i lemon-input-demos\01-requirement-text.txt -o 输入检查.md
python scripts\lemon_checkpoints.py build -i lemon-input-demos\02-requirement-document.md -o 执行清单.xlsx
```

注意：脚本产出的是含占位符的**框架底稿**，业务内容需 Agent 或人工填充；完整参数与示例见 4.2 节。

### 2.8 功能七：技能化集成

**怎么用**

- **安装**：复制技能文件夹到 Qoder 技能目录并重启 IDE（步骤见 3.1 节）。
- **手动触发**：输入 `/lemon-checkpoints` 后跟材料。
- **自动触发**：直接描述任务（如“把这份需求转成测试执行清单”），由模型自动判断调用。

## 3. 安装与验证

使用技能方式**不需要安装任何 Python 依赖**；只有使用本地 CLI 脚本（见 [4.2](#42-方式二本地-cli-脚本)）才需要额外准备 Python 环境。

### 3.1 安装为 Qoder 技能（推荐）

1. **复制整个 `lemon_checkpoints` 文件夹**（必须整个文件夹，内含 `SKILL.md`、`references/`、`scripts/`、`assets/` 等配套文件）到技能目录，建议文件夹命名为 `lemon-checkpoints`：

| 作用域 | 目标位置 | 生效范围 |
|---|---|---|
| 用户级（推荐） | `~/.qoder/skills/lemon-checkpoints/` | 本机所有项目 |
| 项目级 | `<你的项目>/.qoder/skills/lemon-checkpoints/` | 仅该项目 |

Windows PowerShell 示例（用户级，可用 `$env:USERPROFILE` 代替 `~`）：

```powershell
Copy-Item -Recurse "D:\develop\lemon_skills\lemon_checkpoints" "$env:USERPROFILE\.qoder\skills\lemon-checkpoints"
```

> 注意：用户级和项目级存在同名技能时，**项目级优先**。

2. **重启 Qoder IDE**（安装后需要新会话才会加载）。
3. 进入任意项目，对话框输入 `/`，列表中应出现 `lemon-checkpoints` 即安装成功。

### 3.2 可选：本地脚本环境

只有需要用命令行批量生成底稿时才准备：

1. 安装 **Python 3.7 及以上**（建议 3.9+）。
   > 版本过低会报错 `SyntaxError: future feature annotations is not defined`，属正常现象，升级 Python 即可。
2. 安装依赖（仅 Excel 输出需要）：

```powershell
cd D:\develop\lemon_skills\lemon_checkpoints
pip install -r requirements.txt
```

## 4. 三种使用方式

### 4.1 方式一：Qoder 技能（推荐）

安装完成后，有两种触发方式：

- **手动触发**：输入 `/lemon-checkpoints`，随后粘贴或描述材料。
- **自动触发**：直接描述任务，如"把这份需求转成测试执行清单"，模型会自动调用。

**示例对话**

```
/lemon-checkpoints 分析这份登录需求：<粘贴需求文本，或直接附上截图/文档>
```

```
把 lemon-input-demos\02-requirement-document.md 转成测试执行清单，输出到 output 目录
```

**Agent 的行为**：先说明业务背景和材料限制 → 区分已确认事实、验证建议和待确认问题 → 按业务链路和批次生成测试点 → 最后附覆盖地图 → 默认输出 Excel。

**可能的反问**：材料信息不足时，Agent 只会问**最多 6 个**会改变测试结论的问题（其余问题写入交付物的待确认清单），不会打断你太久。

### 4.2 方式二：本地 CLI 脚本

脚本负责**识别、分组和生成框架底稿**，不做业务判断；生成的 Excel/Markdown 中含 `[具体触发情况]` 这类占位符属正常现象，真实测试点内容由 Agent 或人工填充。

**命令一览**

| 命令 | 作用 | 输出 |
|---|---|---|
| `scan`（别名 `inspect`） | 输入检查：识别含糊表达、计算类、智能功能信号 | 输入检查 Markdown |
| `build`（别名 `draft`） | 生成交付物（默认 Excel） | `.xlsx` / Markdown / 脑图 |
| `prompt` | 把材料注入提示词模板 | 可复制提示词 Markdown |

**常用示例**（Windows PowerShell，先进入技能目录）

```powershell
cd D:\develop\lemon_skills\lemon_checkpoints

# 1) 输入检查（不加 -o 时直接打印到屏幕）
python scripts\lemon_checkpoints.py scan -i lemon-input-demos\01-requirement-text.txt -o 输入检查.md

# 2) 生成交付物，默认 Excel
python scripts\lemon_checkpoints.py build -i lemon-input-demos\02-requirement-document.md -o 执行清单.xlsx

# 3) 指定 Markdown 或脑图格式
python scripts\lemon_checkpoints.py build -i lemon-input-demos\02-requirement-document.md -o 执行清单.md --format markdown
python scripts\lemon_checkpoints.py build -i lemon-input-demos\02-requirement-document.md -o 测试脑图.md --format mindmap

# 4) 生成可直接粘贴给任意 AI 的提示词
python scripts\lemon_checkpoints.py prompt -i examples\login-brief.md -o 可复制提示词.md
```

**参数说明**

| 参数 | 说明 |
|---|---|
| `-i / --input` | 必填，输入材料文件路径 |
| `-o / --output` | 输出路径；**Excel 文件名必须以 `.xlsx` 结尾** |
| `--format` | `excel`（默认）/ `markdown` / `mindmap` |
| `--layout` | 兼容 v1.1 的旧参数，等效 `--format`（`table` 等于 `markdown`） |

**不加 `-o` 时的行为**

- `scan`、`prompt`、`markdown`、`mindmap`：内容直接打印到屏幕；
- Excel：在输入文件旁生成 `<原文件名>-测试执行清单.xlsx`。

### 4.3 方式三：提示词模板（不装技能也能用）

打开 `assets/prompt-template.md`，把末尾的占位符

```
[粘贴需求、截图说明、用户故事或接口材料]
```

替换成你的材料，整段复制粘贴给任意 AI 对话，即可获得同样结构的产出。

## 5. 支持的输入材料

| 输入方式 | 示例文件（`lemon-input-demos`） |
|---|---|
| 需求文本 | `01-requirement-text.txt` |
| 需求文档（Markdown） | `02-requirement-document.md` |
| 页面截图 | `03-login-page-screenshot.png` |
| HTML 交互原型 | `04-login-prototype.html` |
| 接口资料（OpenAPI） | `05-openapi.yaml` |
| 多材料组合包 | `06-multi-source-package.zip`（内含 manifest 说明各材料角色和合并规则） |

**材料不完整时的处理原则**

- 截图、原型或一句话需求**可以直接分析**，但只会把可见内容列为事实；
- 登录结果、接口返回、数据写入、权限、失败限制等**不可见行为**，写成"验证建议"并关联待确认问题；
- 高风险的缺口（如未说明的精度、限流、超时规则）会保留为验证建议，不会凭空当成既定规则。

## 6. 交付物说明

### 6.1 Excel（默认）

包含五个固定工作表：

| 工作表 | 内容 | 怎么用 |
|---|---|---|
| 执行看板 | 各批次数量、S0 数量、开放问题数、材料处理方式 | 一眼掌握整体规模和风险分布 |
| 测试清单 | 全部测试点明细（触发情况、样本数据、核对结果、依据、严重度、执行方式、失败影响等 12 列） | 执行主体，按批次/严重度筛选 |
| 待确认 | 开放问题、影响测试点、风险、负责人、状态、确认结论 | 交给产品/开发确认的跟踪清单 |
| 规则证据 | 已确认事实（F-XXX）和验证建议（V-XXX） | 核对每条测试点的依据来源 |
| 覆盖地图 | C01–C14 的状态、关联测试点、当前缺口 | 评审时查漏、解释缺口原因 |

阅读提示：

- 严重度用颜色区分：S0 浅红、S1 浅橙、S2 浅黄、S3 不强调；证据级别看文字列，不用颜色代替。
- 每个 `O-XXX` 至少关联一条测试点；**没有待确认问题时，"待确认"表也会保留并注明"无"**，避免评审误判为漏项。
- 表头冻结、已启用筛选，可直接过滤使用。

### 6.2 Markdown / 脑图（按需）

- **Markdown**：在指令中明确要求即可切换。内容顺序为背景和材料边界 → 输入底稿 → 待确认清单 → 风险路线 → 执行清单 → 覆盖地图，各自独立成节。
- **脑图（飞书/XMind 大纲）**：根节点唯一，一级节点按 A/B/C 批次组织，覆盖地图放在末尾。

### 6.3 输出路径约定

- 未指定路径时，写入 `output/lemon-checkpoints/<需求简称>-测试执行清单.xlsx`；
- 指定了路径则以你指定的为准；
- 建议按需求维度建立子目录（如 `output/lemon-checkpoints/智汇ERP登录/`），便于版本管理。

|---|---|---|
| 1. 准备材料 | 确认需求文本/截图/原型等材料就绪 | 材料越完整，事实越多、待确认越少 |

## 8. 常见问题 FAQ

**Q1：执行脚本报 `SyntaxError: future feature annotations is not defined`？**
Python 版本低于 3.7。安装 Python 3.7+（建议 3.9+）后用新解释器运行；如果只是想出结果，可以完全跳过脚本，直接用技能方式（4.1）。

**Q2：执行脚本报 `Excel输出需要 openpyxl`？**
Excel 输出依赖 openpyxl，在技能目录执行：`pip install -r requirements.txt`。

**Q3：输入 `/` 找不到 `lemon-checkpoints`？**
依次检查：① 文件夹是否复制到了正确的 skills 目录；② 目录内是否存在 `SKILL.md`；③ 是否重启了 IDE；④ 是否存在项目级同名技能覆盖了用户级。全部无误后在新会话中重试。

**Q4：生成的 Excel 里全是 `[具体触发情况]` 这类占位符？**
这是 CLI 脚本的**框架底稿**模式，属正常现象——脚本只负责识别、分组和排版，不做业务判断。真实测试点内容需要让 Agent 基于同样材料生成，或人工填充。

**Q5：交付物默认保存在哪？**
`output/lemon-checkpoints/<需求简称>-测试执行清单.xlsx`。可以在指令中直接指定路径，如"输出到 `D:\test\登录清单.xlsx`"。

**Q6：只有一张截图或一句话需求，能分析吗？**
可以。只会把可见内容列为事实，不可见行为写成验证建议并关联待确认问题，不会编造规则。

**Q7：会不会问一堆问题打断工作？**
不会。Agent 只问**会改变测试结论**的问题，最多 6 个；其余问题全部写入交付物的"待确认"工作表。

**Q8：输出格式能换吗？**
可以。默认 Excel；在指令中明确说"输出 Markdown"或"输出脑图"即可切换，CLI 用 `--format markdown` / `--format mindmap`。

**Q9：它和"写测试用例"有什么区别？**
本技能输出到**测试点**级别：每条写明触发情况、样本数据、可核对结果、依据、严重度和失败影响，但不写逐步操作步骤，也不替代完整测试计划。
