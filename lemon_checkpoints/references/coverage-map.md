# 覆盖地图

覆盖地图在测试清单生成后使用。它负责发现遗漏，不要求每个方向都生成固定数量的测试点。

| 代码 | 检查方向 | 核心问题 |
|---|---|---|
| C01 | 成功路径 | 用户能否完成主要目标及关键分支 |
| C02 | 失败反馈 | 输入、操作、网络和依赖失败是否可理解、可恢复 |
| C03 | 临界条件 | 数值、长度、数量、时间、空值及特殊输入是否覆盖 |
| C04 | 访问控制 | 身份、角色、跨账号访问和权限变化是否安全 |
| C05 | 数据约束 | 必填、格式、范围、唯一性和关联关系是否一致 |
| C06 | 生命周期 | 初始、处理中、成功、失败、取消和终态是否正确 |
| C07 | 同时操作 | 竞争、覆盖、锁、重复创建和资源超限是否可控 |
| C08 | 重复与重试 | 连续提交、网络重传和失败重试是否产生重复结果 |
| C09 | 服务契约 | 参数、返回、版本、限流、降级和错误处理是否稳定 |
| C10 | 持久化 | 新增、更新、事务、回滚和读写一致性是否正确 |
| C11 | 追溯能力 | 操作、结果和必要上下文是否留痕，敏感字段是否隐藏 |
| C12 | 运行环境 | 浏览器、系统、设备、分辨率、网络和旧数据是否支持 |
| C13 | 容量指标 | 响应时间、吞吐、并发、资源和长时间运行是否达标 |
| C14 | 变更影响 | 核心冒烟、关联模块、旧接口、配置及历史数据是否受影响 |

状态只使用三种：

- `已覆盖`：存在可执行测试点。
- `待补充`：方向适用，但缺少规则、数据或环境。
- `不适用`：与本次业务没有合理触发关系，并写明原因。
