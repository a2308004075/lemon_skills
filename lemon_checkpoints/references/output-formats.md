# 交付规范

## Excel（默认）

默认交付格式。工作簿采用五个工作表：

1. `执行看板`：显示各批次数量、S0/S1数量、开放问题和高风险路线。
2. `测试清单`：完整明细，启用筛选并冻结首行。
3. `待确认`：独立列出开放问题、关联测试点、风险、负责人、状态和确认结论。禁止仅在其他工作表中引用问题编号。
4. `规则证据`：保存已确认事实和验证建议，也可以保留全部问题的追溯记录。
5. `覆盖地图`：记录14个检查方向的状态、关联测试点和缺口。

每个 `O-XXX` 至少关联一条测试点。没有待确认问题时也要创建 `待确认` 工作表，写明“当前无待确认问题”，避免评审人员误判为漏项。

严重度颜色：S0浅红、S1浅橙、S2浅黄、S3不强调。证据级别使用单独列，不用颜色代替文字。长文本自动换行，禁止使用合并单元格制作复杂表头。

未指定输出路径时，建议落盘到 `output/lemon-checkpoints/<需求简称>-测试执行清单.xlsx`。

## Markdown（按需）

仅在用户明确要求 Markdown 时使用。按下面顺序输出：

1. 背景和材料边界。
2. 输入底稿：已确认事实、验证建议、待确认问题。
3. 待确认清单：问题编号、问题、影响测试点、风险、负责人、状态、确认结论。
4. 风险路线。
5. 测试执行清单。
6. 覆盖地图。

不要把所有内容塞进一张超宽表。输入底稿、执行清单和覆盖地图各自独立。

## 飞书或XMind大纲

根节点只有一个。一级节点按执行批次组织，覆盖地图独立放在末尾。

```markdown
# [需求名称]测试执行图

- A 首轮冒烟
  - LC-001 [S0] 业务链路｜触发情况
    - 数据：具体样本
    - 结果：可核对结果
    - 依据：F-001

- B 重点验证
  - LC-002 [S1] 业务链路｜触发情况
    - 数据：具体样本
    - 结果：可核对结果
    - 依据：O-001

- 覆盖地图
  - C01 成功路径｜已覆盖｜LC-001
```
